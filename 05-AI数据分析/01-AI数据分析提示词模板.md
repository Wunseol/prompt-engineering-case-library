## 一、SQL 查询生成

### 适用场景
根据自然语言描述生成 SQL 查询语句，支持 MySQL、PostgreSQL、SQLite 等主流数据库。

### 模板
```
你是一位资深数据库工程师，精通 SQL 优化和查询设计。

数据库类型：{MySQL/PostgreSQL/SQLite/其他}
表结构：
{粘贴表结构 DDL 或描述}

请根据以下需求生成 SQL 查询：

需求：{自然语言描述的查询需求}

约束：
- 使用标准 SQL，兼容{数据库类型}语法
- 对复杂查询添加注释说明逻辑
- 考虑查询性能，合理使用索引提示
- 如果需求不明确，列出假设并给出多个版本

输出格式：
## 查询语句
​```sql
{SQL代码}
​```

## 逻辑说明
{逐行解释关键逻辑}

## 性能提示
{如有性能风险，给出优化建议}
```

### 示例
需求："查询每个部门薪资最高的3名员工"
```sql
-- 使用窗口函数，高效获取分组TopN
SELECT * FROM (
    SELECT 
        d.dept_name,
        e.emp_name,
        e.salary,
        ROW_NUMBER() OVER (PARTITION BY e.dept_id ORDER BY e.salary DESC) AS rn
    FROM employees e
    JOIN departments d ON e.dept_id = d.id
) ranked
WHERE rn <= 3
ORDER BY dept_name, rn;
```

## 二、数据解读与洞察提取

### 适用场景
对数据表格、CSV 内容或统计结果进行深度解读，提取关键洞察。

### 模板
```
你是一位高级数据分析师，擅长从数据中发现业务洞察。

请分析以下数据：

数据背景：{业务场景描述，如"电商平台月度销售数据"}
数据内容：
{粘贴数据表格或 CSV 内容}

分析要求：
1. 提取 3-5 个关键洞察（趋势、异常、关联）
2. 每个洞察给出：发现 → 可能原因 → 业务影响 → 建议行动
3. 识别数据中的异常值或潜在数据质量问题
4. 指出需要进一步分析的维度

约束：
- 洞察必须基于数据，不猜测无依据的结论
- 区分相关性和因果性
- 对不确定的结论标注置信度（高/中/低）
- 使用简洁的语言，避免统计术语

输出格式：
## 关键洞察
### 洞察1：{标题}
- **发现**：{数据事实}
- **可能原因**：{1-2个可能原因}
- **业务影响**：{正面/负面影响}
- **建议行动**：{具体可执行的建议}
- **置信度**：{高/中/低}

## 数据质量备注
{异常值、缺失值等}

## 建议的下一步分析
{需要深挖的方向}
```

**真实输入→输出示例**：

输入：`数据背景：某SaaS产品月度活跃数据，2024年1月-6月`

| 月份 | MAU | 新增用户 | 付费转化率 | 流失率 |
|------|-----|---------|----------|-------|
| 1月 | 12000 | 3000 | 4.2% | 5.1% |
| 2月 | 11800 | 2800 | 4.0% | 6.8% |
| 3月 | 12500 | 3500 | 4.5% | 5.3% |
| 4月 | 12100 | 2900 | 3.8% | 7.2% |
| 5月 | 13200 | 4200 | 5.1% | 4.8% |
| 6月 | 12800 | 3100 | 4.3% | 6.5% |

输出：
```
## 关键洞察

### 洞察1：流失率与付费转化率呈负相关
- **发现**：2月和4月流失率飙升（6.8%/7.2%），同期付费转化率下降（4.0%/3.8%）
- **可能原因**：① 产品更新引入bug导致体验下降 ② 竞品同期推出优惠活动
- **业务影响**：高流失+低转化=收入双重下降
- **建议行动**：排查2月和4月的产品变更记录，对比竞品动态
- **置信度**：中

### 洞察2：5月新增用户暴增但未持续
- **发现**：5月新增4200（环比+45%），但6月回落至3100
- **可能原因**：5月有一次性营销活动或渠道曝光
- **业务影响**：如无法复制，6月回落属于正常回归
- **建议行动**：分析5月新增用户来源渠道，评估哪些可复用
- **置信度**：高

### 洞察3：单数月份流失率普遍高于双数月份
- **发现**：2/4/6月流失率均高于1/3/5月（6.8% vs 5.1%, 7.2% vs 5.3%, 6.5% vs 4.8%）
- **可能原因**：月末账单周期影响，或季末考核导致用户流失
- **业务影响**：如存在周期性，可在高流失月前置干预
- **建议行动**：拉取更长时间数据验证此规律是否稳定
- **置信度**：低（数据点太少）

## 数据质量备注
- 仅6个月数据，趋势判断可能不可靠
- 流失率定义需确认（30天未登录？取消订阅？）

## 建议的下一步分析
1. 补充12个月数据验证季节性规律
2. 按用户来源渠道拆分新增用户
3. 分析流失用户的行为特征（功能使用频率、最后一次操作）
```

## 三、统计分析与假设检验

### 适用场景
设计实验方案、选择统计方法、解读假设检验结果。

### 模板
```
你是一位统计学专家，擅长实验设计和统计推断。

请为以下场景设计统计分析方案：

研究问题：{要验证的假设}
数据类型：{连续型/分类型/有序型}
样本量：{预计样本量或已有样本量}
组别：{几组，是否配对}

请提供：
1. 推荐的统计检验方法及理由
2. 前提假设检查清单
3. 效应量估计方法
4. 结果解读框架
5. 常见误区提醒

约束：
- 给出方法选择决策树（什么情况用什么方法）
- 用通俗语言解释统计概念
- 标注每个方法的适用条件
- 如有多种方案，对比优劣

输出格式：
## 推荐方法
{方法名称及选择理由}

## 前提检查
- [ ] {检查项1}
- [ ] {检查项2}

## 分析步骤
1. {步骤1}
2. {步骤2}

## 结果解读
- p < 0.05 意味着：{通俗解释}

## 常见误区

## 四、数据可视化建议

### 适用场景
根据数据特征和表达目标，推荐最佳图表类型和可视化方案。

### 模板
```
你是一位数据可视化专家，精通图表选型和叙事化展示。

请为以下数据推荐可视化方案：

数据描述：{数据内容概述}
表达目标：{比较/趋势/分布/关系/构成/排名}
受众：{技术人员/管理层/公众}
工具：{Excel/Tableau/ECharts/Matplotlib/其他}

请提供：
1. 推荐的主图表类型及理由
2. 备选方案（如果主方案不合适）
3. 图表设计要点
4. 配色建议
5. 交互建议（如适用）

约束：
- 图表选择遵循"数据→目标→图表"决策逻辑
- 优先选择受众容易理解的图表
- 给出避免的图表类型及原因

输出格式：
## 推荐图表：{图表名称}

**选择理由**：{为什么选这个图表}

**设计要点**：
- X轴：{字段}
- Y轴：{字段}
- 颜色编码：{字段}
- 标注重点：{需要突出的数据点}

**配色方案**：{推荐色系}

**避免使用**：{不推荐的图表}，原因是{原因}

## 备选方案
{如适用}
```

### 图表选择速查

| 表达目标 | 推荐图表 | 避免图表 |
|---------|---------|---------|
| 比较数值 | 柱状图、条形图 | 饼图（超过5类） |
| 展示趋势 | 折线图、面积图 | 柱状图（连续时间） |
| 显示分布 | 直方图、箱线图、小提琴图 | 折线图 |
| 展示关系 | 散点图、气泡图 | 柱状图 |
| 显示构成 | 饼图（≤5类）、树状图 | 堆叠柱状图（类别多时） |
| 展示排名 | 条形图 | 饼图 |

## 九、使用技巧

| 技巧 | 说明 |
|------|------|
| 先给表结构 | 生成 SQL 时，先提供 DDL 或表结构描述，准确率大幅提升 |
| 提供样本数据 | 数据解读时，给 5-10 行真实样本比描述更有效 |
| 明确数据库类型 | 不同数据库 SQL 语法差异大（如 LIMIT vs TOP） |
| 分步分析 | 复杂分析拆成：数据概览 → 异常检测 → 深入分析 → 结论 |
| 要求给出代码 | 同时获取分析逻辑和可复现代码 |
| 标注不确定性 | 要求 AI 对不确定结论标注置信度，避免误导 |

## 十、常见问题 FAQ

| 问题 | 解答 |
|------|------|
| AI 生成 SQL 有错误怎么办？ | 始终提供表结构，要求 AI 解释逻辑，人工审核后再执行 |
| AI 能处理多大的数据？ | 直接粘贴建议不超过 500 行，大数据用描述+统计摘要代替 |
| 统计分析结果可信吗？ | AI 擅长推荐方法，但 p 值等计算需用专业工具验证 |
| 如何让 AI 画出图表？ | AI 可生成 ECharts/Matplotlib 代码，但无法直接渲染图表 |
| 数据隐私怎么保护？ | 不要粘贴真实敏感数据，使用脱敏样本或模拟数据 |
