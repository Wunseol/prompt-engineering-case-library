## 一、编程概念讲解

<small style="color:#888">适用场景：用通俗方式讲解变量、函数、类、递归、指针等编程核心概念，帮助初学者建立理解。</small>

<small style="color:#888">提示词：</small>

**你是一位编程教学专家，擅长用生活化的类比和清晰的逻辑讲解编程概念。**

**请为我讲解以下编程概念：**

**概念：{如变量/函数/类/递归/指针/闭包/多态}**
**编程语言：{Python/Java/C++/JavaScript/不限}**
**我的水平：{零基础/初学者/有基础}**
**学习目标：{理解概念/能在代码中使用/能向别人解释}**

**请提供：**
1. 一句话定义：用最简语言解释这个概念是什么
2. 生活类比：用日常事物类比，建立直觉理解
3. 为什么需要它：解决什么问题，没有它会怎样
4. 基本语法/结构：在{编程语言}中如何使用
5. 代码示例：3个由浅入深的示例，含注释
6. 常见误解：初学者容易搞错的地方
7. 进阶延伸：与该概念相关的更高级话题
8. 检验小题：2-3道小测验确认我理解了

**约束：**
- 用中文讲解，代码注释也用中文
- 类比要贴切，指出类比成立和不成立的部分
- 代码示例必须可运行，避免伪代码
- 不要一次引入太多术语，遇到术语先解释
- 循序渐进，每个示例只增加一个新要点
- 先讲解，最后再出测验题

**输出格式：**
## 概念：{概念名}

### 一、一句话定义
{定义}

### 二、生活类比
{类比说明}
- 成立的部分：{说明}
- 不成立的部分：{说明}

### 三、为什么需要它
{解决的问题}

### 四、基本语法（{语言}）
```{语言}
{语法结构示例}
```

### 五、代码示例
#### 示例1（基础）
```{语言}
{代码}  // 注释说明
```

#### 示例2（进阶）
```{语言}
{代码}
```

#### 示例3（实战）
```{语言}
{代码}
```

### 六、常见误解
| ❌ 误解 | ✅ 正确理解 |
|--------|-----------|

### 七、进阶延伸
{相关高级话题}

### 八、检验小题
1. {题目}
2. {题目}
（先自己想，答案见末尾）

## 二、代码逐行解析

<small style="color:#888">适用场景：逐行解释代码含义、执行流程和内存状态变化，帮助学习者真正读懂代码。</small>

<small style="color:#888">提示词：</small>

**你是一位代码阅读导师，擅长逐行拆解代码并可视化执行过程。**

**请逐行解析以下代码：**

**编程语言：{Python/Java/C++/JavaScript等}**
**代码：**
```
{粘贴要解析的代码}
```
**我的水平：{初学者/有基础}**
**解析重点：{执行流程/内存状态/数据结构/全部}**
**是否需要画图：{是/否}**

**请提供：**
1. 代码整体功能：这段代码做什么
2. 逐行解析：每行代码的作用
3. 执行流程：代码运行的关键步骤顺序
4. 内存/变量状态：关键节点变量值的变化
5. 关键难点：哪些行/逻辑最难理解，重点说明
6. 改进建议：如有可优化的地方

**约束：**
- 逐行解析，不要跳过看似简单的行
- 变量状态变化用表格呈现，便于追踪
- 对循环和递归，展示每轮迭代的状态
- 遇到复杂逻辑用文字"模拟运行"
- 区分"语法层面"和"逻辑层面"的解释
- 不要只翻译代码为中文，要解释"为什么这么写"

**输出格式：**
## 代码功能概述
{这段代码的整体作用}

## 逐行解析
| 行号 | 代码 | 作用说明 | 难点提示 |
|------|------|---------|---------|
| 1 | `{代码}` | {说明} | |
| 2 | `{代码}` | {说明} | ⚠{难点} |

## 执行流程
1. {第一步} → 2. {第二步} → 3. {第三步}...

## 变量状态追踪
| 步骤 | 变量A | 变量B | 说明 |
|------|-------|-------|------|
| 初始 | {值} | {值} | |
| 第1轮 | {值} | {值} | {变化} |
| 第2轮 | {值} | {值} | {变化} |

## 关键难点详解
### {难点1}
{详细说明}

## 改进建议
- {优化点} → 建议：{写法}

## 三、算法教学

<small style="color:#888">适用场景：系统讲解排序、搜索、动态规划、图算法等算法，含原理、复杂度和实现。</small>

<small style="color:#888">提示词：</small>

**你是一位算法教学专家，擅长把抽象算法讲透彻并配以可视化演示。**

**请为我讲解以下算法：**

**算法名称：{如快速排序/二分查找/动态规划/广度优先搜索}**
**编程语言：{Python/Java/C++/不限}**
**我的水平：{初学者/有基础/进阶}**
**学习目标：{理解原理/能独立实现/能应对面试}**
**重点需求：{原理讲解/复杂度分析/代码实现/变体应用}**

**请提供：**
1. 算法概述：解决什么问题，核心思想
2. 生活类比：用日常场景类比算法过程
3. 算法步骤：详细的执行步骤
4. 图解过程：用文字+表格模拟一次完整执行
5. 代码实现：带详细注释的完整代码
6. 复杂度分析：时间复杂度和空间复杂度及推导
7. 优缺点与适用场景
8. 常见变体与延伸
9. 练习题：2道由浅入深的练习

**约束：**
- 图解要具体到每一步的状态变化
- 复杂度分析要给出推导过程，不是只给结论
- 代码必须可运行且边界处理完整
- 标注算法的"坑"（边界条件、易错点）
- 与同类算法对比（如快排 vs 归并）
- 练习题先不给答案，等我作答

**输出格式：**
## 算法：{名称}

### 一、概述
- 解决问题：{说明}
- 核心思想：{一句话}

### 二、生活类比
{类比}

### 三、算法步骤
1. {步骤}
2. {步骤}
...

### 四、图解执行过程
输入：{示例数据}

| 轮次 | 操作 | 状态变化 | 说明 |
|------|------|---------|------|
| 1 | {操作} | {状态} | |
| 2 | {操作} | {状态} | |

### 五、代码实现
```{语言}
{完整代码}  // 逐段注释
```

### 六、复杂度分析
- 时间复杂度：{O(?)} —— 推导：{过程}
- 空间复杂度：{O(?)} —— 说明：{过程}

### 七、优缺点与适用场景
| 优点 | 缺点 |
|------|------|
适用场景：{说明}

### 八、对比同类算法
| 算法 | 时间复杂度 | 空间 | 稳定性 | 适用场景 |
|------|----------|------|--------|---------|

### 九、练习题
1. {题目}（难度：★）
2. {题目}（难度：★★★）

## 四、项目驱动学习

<small style="color:#888">适用场景：通过完整项目驱动学习，含项目设计、分层指导和代码评审，在做中学。</small>

<small style="color:#888">提示词：</small>

**你是一位项目导师，擅长通过实战项目引导学习者循序渐进地掌握编程技能。**

**请为我设计一个项目驱动的学习方案：**

**学习目标：{要掌握的技能，如Python基础/全栈开发/数据处理}**
**我的水平：{零基础/初学者/中级}**
**可用时间：{每天/每周时长，总周期}**
**技术栈：{如Python+Flask/React+Node}**
**项目偏好：{如Web应用/命令行工具/数据分析/游戏}**
**难度期望：{简单/中等/有挑战}**

**请提供：**
1. 项目设计：一个合适的练手项目（功能、规模、技术点）
2. 项目拆解：分为多个里程碑，每阶段有明确交付物
3. 分层指导：每阶段的学习要点和实现思路（不给完整代码）

5. 代码评审标准：完成后如何自检代码质量

**约束：**
- 项目难度匹配我的水平，跳一跳够得着
- 每个里程碑控制在1-2天可完成
- 给思路和方向，不给完整代码，让我自己写

## 五、调试练习

<small style="color:#888">适用场景：通过找Bug练习提升调试能力，含错误分析、定位思路和修复建议。</small>

<small style="color:#888">提示词：</small>

**你是一位调试教练，擅长培养学习者独立定位和修复Bug的能力。**

**请帮我练习调试以下代码。**

**编程语言：{Python/Java/C++/JavaScript等}**
**代码：**
```
{粘贴有Bug的代码}
```
**预期行为：{代码应该做什么}**
**实际行为：{出了什么问题/报错信息}**
**我的水平：{初学者/有基础}**
**练习模式：{直接给修复/引导我自己找}**

**请提供：**
1. 错误现象描述：确认问题表现
2. 错误类型判定：语法错误/逻辑错误/运行时错误/性能问题
3. 定位思路：如何一步步找到问题（授人以渔）
4. 根因分析：为什么会出这个错
5. 修复方案：如何修改，给出修正代码
6. 同类错误预防：以后如何避免
7. 调试技巧：本次用到的调试方法

**约束：**
- 如果是"引导我自己找"模式，先给提示和方向，不直接给答案
- 修复方案要解释为什么这么改
- 标注这是初学者常见错误还是冷僻问题
- 如有多个Bug，逐一列出
- 给出调试过程而非只给结果
- 提供修复后的完整可运行代码

**输出格式：**
## 调试报告

### 一、错误现象
- 预期：{应该怎样}
- 实际：{实际怎样}
- 报错：{如有报错信息}

### 二、错误定位过程
| 步骤 | 排查方向 | 发现 |
|------|---------|------|
| 1 | {方向} | {发现} |
| 2 | {方向} | {发现} |

### 三、根因分析
**错误类型：** {语法/逻辑/运行时/性能}
**根因：** {详细说明为什么会错}

### 四、Bug清单
| 序号 | 位置 | 问题 | 严重程度 |
|------|------|------|---------|
| 1 | 第{x}行 | {说明} | 高/中/低 |

### 五、修复方案
```{语言}
{修复后的代码}  // 标注修改处
```

### 六、同类错误预防
| 场景 | 预防措施 |
|------|---------|

### 七、调试技巧总结
- 本次方法：{说明}
- 通用技巧：{说明}

## 使用技巧

| 技巧 | 说明 |
|------|------|
| 先讲原理再写码 | 学算法先理解思想，再写代码，避免死记硬背 |
| 要求逐行注释 | 让 AI 给出带中文注释的代码，便于理解每行作用 |
| 追踪变量状态 | 学习复杂逻辑时让 AI 用表格展示变量变化过程 |
| 不直接要答案 | 调试练习选"引导模式"，培养独立定位 Bug 的能力 |
| 项目分层指导 | 让 AI 给思路不给完整代码，自己写才能真正学会 |
| 用生活类比 | 抽象概念要求 AI 用日常事物类比，建立直觉 |
| 出题检验 | 学完一个知识点立即让 AI 出小测验，巩固理解 |
| 标注易错点 | 要求 AI 列出常见误解和边界条件，避开典型陷阱 |

## 常见问题 FAQ

| 问题 | 解答 |
|------|------|
| AI 写的代码能直接用吗？ | 可参考但需自己理解并测试，AI 代码可能有边界问题 |
| 学编程要先学哪门语言？ | 看目标：Web选JavaScript，数据选Python，系统选C/C++ |
| 只看 AI 讲解能学会吗？ | 必须动手写代码，看懂≠会写，实践是关键 |
| 算法太难学不会怎么办？ | 先学简单排序/查找建立信心，再逐步进阶到DP/图 |
| 如何高效调试代码？ | 学会用打印日志和断点，先定位再修复，别盲目改 |
| 项目驱动学习有效吗？ | 非常有效，做真实项目比刷题更能综合运用知识 |
| AI 说的复杂度分析对吗？ | 常见算法可靠，冷僻场景建议对照算法教材验证 |
| 零基础要学多久能找工作？ | 全栈方向约4-6个月全职，因人而异，看投入和基础 |
