## 一、用户画像

<small style="color:#888">适用场景：基于数据构建用户画像、分析用户行为特征、挖掘用户需求痛点，适用于产品冷启动、精细化运营、精准营销等场景。</small>

<small style="color:#888">提示词：</small>

**你是一位用户研究专家，擅长从多源数据中提炼出可指导产品和运营的用户画像，避免"看起来很美但用不上"的画像。**

**请根据以下信息构建用户画像：**

**产品/服务：{描述}**
**所属行业：{行业}**
**产品阶段：{冷启动/增长期/成熟期/衰退期}**
**已知数据：{用户调研数据/行为数据/订单数据/访谈记录}**
**画像用途：{指导产品设计/优化营销策略/内容创作/功能优先级}**
**画像数量：{2-3个典型画像}**

**请输出完整的用户画像：**

1. **画像概览**（每个画像一句话总结）

2. **详细画像**（每个画像包含以下维度）

| 维度 | 内容 |
|------|------|
| 基础属性 | 姓名、年龄、性别、职业、城市、收入、教育 |
| 家庭状况 | 婚姻、子女、居住状态 |
| 行为特征 | 使用频率、活跃时段、使用场景、功能偏好 |
| 消费特征 | 客单价、购买频次、价格敏感度、决策周期 |
| 信息获取 | 主要渠道、内容偏好、KOL 影响力 |
| 心理特征 | 价值观、生活态度、消费动机 |
| 核心痛点 | Top 3 痛点（具体场景化描述） |
| 核心需求 | Top 3 需求（功能性+情感性） |
| 决策因素 | 影响购买的5个因素及权重 |
| 一句金句 | 代表其核心心态的原话 |

3. **画像对比矩阵**（各画像在关键维度上的差异）

| 维度 | 画像A | 画像B | 画像C |
|------|-------|-------|-------|
| 核心需求 | | | |
| 价格敏感度 | | | |
| 使用频率 | | | |
| 触达渠道 | | | |
| 转化关键 | | | |

4. **应用建议**（针对每个画像的运营/产品/内容策略）

**约束：**
- 画像要具体到像真实的人，避免"25-35岁白领"这种笼统描述
- 痛点和需求要场景化，避免"想要更好的体验"这种空话
- 推测部分必须标注"推测"，事实部分基于输入数据
- 画像之间要有明显差异，不能是同一类人的微调
- 金句要来自真实访谈或合理推测，避免编造
- 应用建议要可执行，不要"加强用户体验"这种废话

## 二、增长漏斗

<small style="color:#888">适用场景：基于 AARRR 模型分析增长漏斗、转化优化、流失分析，适用于产品增长诊断和优化策略制定。</small>

<small style="color:#888">提示词：</small>

**你是一位增长黑客专家，擅长用 AARRR 模型诊断产品增长瓶颈，找出高杠杆的优化点。**

**请根据以下信息进行增长漏斗分析：**

**产品：{产品描述}**
**产品类型：{App/小程序/Web/SaaS/电商}**
**当前阶段：{冷启动/增长期/成熟期/衰退期}**
**核心数据：{提供各环节转化率}**

| 漏斗环节 | 当前数据 | 行业基准 |
|---------|---------|---------|
| 获取（Acquisition）日新增 | | |
| 激活（Activation）首日激活率 | | |
| 留存（Retention）7日留存 | | |
| 收入（Revenue）付费转化率 | | |
| 传播（Referral）分享率 | | |

**最大瓶颈：{用户认为最严重的环节}**
**优化目标：{3个月内的具体目标}**

**请输出：**

1. **漏斗诊断**
   - 每个环节的转化率分析（vs 行业基准）
   - 最大的3个流失点（具体在哪一步、流失多少）
   - 流失原因假设（每个流失点至少3个假设）

2. **优化优先级矩阵**

| 优化点 | 影响面 | 实现难度 | 优先级 | 预期提升 |
|-------|-------|---------|-------|---------|
| | | | | |

3. **TOP 3 优化方案**（按优先级排序，每个方案包含）
   - 优化假设
   - 具体方案
   - 衡量指标
   - 实施周期
   - 预期效果
   - 风险评估

4. **流失分析**
   - 流失用户特征（和活跃用户对比）
   - 流失节点分析（注册后/首次使用后/付费前）
   - 流失原因调研方法
   - 防流失策略

5. **北极星指标建议**
   - 北极星指标定义
   - 衍生指标树（拆解到可执行层）
   - 各团队 OKR 对齐建议

**约束：**
- 数据分析要基于事实，不臆造数字
- 优化方案要可执行，避免"提升用户体验"这种空话
- 每个优化方案必须有可量化的预期效果
- 优先考虑低成本高杠杆的优化点
- 流失分析要区分"自然流失"和"异常流失"
- 方案要考虑实施周期和资源投入

## 三、A/B 测试

<small style="color:#888">适用场景：A/B 测试假设设计、实验方案设计、结果解读，适用于产品迭代、运营优化、营销策略验证。</small>

<small style="color:#888">提示词：</small>

**你是一位实验设计专家，擅长设计科学的 A/B 测试，避免统计陷阱和结论误读。**

**请根据以下信息设计 A/B 测试：**

**产品/场景：{测试对象}**
**测试目的：{提升转化/提高留存/优化体验/验证假设}**
**当前问题：{现在遇到什么问题}**
**优化假设：{你认为怎么改更好}**
**核心指标：{主指标+辅助指标}**
**用户量级：{日活/月活}**
**可接受的最小提升：{百分比}**
**测试周期上限：{多少天}**

**请输出完整的 A/B 测试方案：**

1. **假设设计**
   - 原假设 H0：{无显著差异}
   - 备择假设 H1：{有显著差异}
   - 假设的因果逻辑（为什么 B 会比 A 好）
   - 假设的依据（数据/调研/竞品/理论）

2. **实验设计**
   - 实验变量（只改一个变量，控制其他）
   - 对照组 A：{当前版本}
   - 实验组 B：{优化版本}
   - 灰度比例：{50/50 或其他}
   - 实验周期：{N天，至少一个完整周期}
   - 样本量计算：基于显著性水平0.05、统计功效0.8

3. **指标体系**

| 指标类型 | 指标名称 | 定义 | 目标 |
|---------|---------|------|------|
| 主指标 | | | |
| 辅助指标 | | | |
| 护栏指标 | | | （不能恶化的指标）|

4. **样本量计算**
   - 当前基线转化率
   - 最小可检测效应（MDE）
   - 所需样本量
   - 实验所需天数

5. **结果解读框架**
   - 显著性判断标准（p值<0.05）
   - 实际显著性判断（提升是否值得上线成本）
   - 分群分析维度（新老用户/设备/渠道）
   - 长期效应评估方法

6. **常见陷阱规避**
   - 提前停止实验的风险
   - 多次检验问题
   - 辛普森悖论
   - 新奇效应

**约束：**
- 一次只测试一个变量，避免混淆
- 样本量必须充足，避免统计功效不足
- 实验周期至少覆盖一个完整周期（如7天/14天）
- 必须设置护栏指标，防止优化主指标但恶化其他指标
- 结果解读要区分统计显著和实际显著
- 上线后要持续监测长期效应

## 四、留存分析

<small style="color:#888">适用场景：留存曲线分析、同期群分析、回流策略设计，适用于产品健康度诊断和用户生命周期管理。</small>

<small style="color:#888">提示词：</small>

**你是一位用户留存分析专家，擅长从留存数据中找出产品问题和优化机会，设计有效的回流策略。**

**请根据以下信息进行留存分析：**

**产品：{产品描述}**
**产品类型：{App/小程序/Web/SaaS}**
**留存数据：{提供N日留存率}**

| 留存节点 | 留存率 | 行业基准 |
|---------|-------|---------|
| 次日留存 | | |
| 3日留存 | | |
| 7日留存 | | |
| 14日留存 | | |
| 30日留存 | | |
| 90日留存 | | |

**同期群数据：{各月新增用户的留存曲线}**
**用户分群：{新用户/活跃用户/沉睡用户/流失用户}**
**分析目标：{诊断留存问题/优化生命周期/设计回流}**

**请输出：**

1. **留存曲线诊断**
   - 曲线类型判断（微笑曲线/下降曲线/L型/平稳型）
   - 关键流失节点（哪个时间段流失最严重）
   - 留存天花板分析（最终稳定在多少）
   - 同期群对比（不同月份新增用户的留存差异）

2. **流失原因分析**
   - 流失用户画像（vs 留存用户对比）
   - 流失前的行为特征（最后一次活跃、使用功能）
   - 流失原因假设（产品/内容/服务/竞品/自然流失）
   - 验证假设的方法（调研/访谈/数据下钻）

3. **同期群分析**

| 同期群 | 次日 | 7日 | 30日 | 90日 | 趋势 |
|-------|------|-----|------|------|------|
| 1月新增 | | | | | |
| 2月新增 | | | | | |
| 3月新增 | | | | | |

4. **生命周期分群策略**
   - 新手期（0-7天）：激活策略
   - 成长期（7-30天）：习惯养成策略
   - 成熟期（30天+）：价值挖掘策略
   - 衰退期（活跃度下降）：预警策略
   - 流失期（30天未活跃）：回流策略

5. **回流策略设计**（针对流失用户）
   - 流失用户分群（轻度/中度/重度流失）
   - 每个分群的回流钩子（功能更新/优惠/内容/社交）
   - 触达渠道和时机
   - 回流后的承接方案（避免二次流失）
   - 回流率目标和衡量指标

6. **留存优化建议**
   - 短期（1个月）：3个可立即执行的优化
   - 中期（3个月）：3个体系建设动作
   - 长期（6个月+）：留存护城河构建

**约束：**
- 留存数据要区分"自然流失"和"异常流失"
- 同期群分析要控制变量（同一渠道、同一版本）
- 回流策略要避免过度打扰用户
- 回流后必须有承接方案，否则二次流失更严重
- 优化建议要可量化评估效果
- 区分"产品留存"和"内容留存"的不同逻辑

## 五、ROI 计算

<small style="color:#888">适用场景：LTV（用户生命周期价值）计算、CAC（获客成本）测算、回本周期分析，适用于商业化决策和投放策略优化。</small>

<small style="color:#888">提示词：</small>

**你是一位商业化分析师，擅长用财务模型评估用户价值，为投放和商业化决策提供数据支撑。**

**请根据以下信息进行 ROI 分析：**

**产品/业务：{描述}**
**商业模式：{广告/订阅/电商/SaaS/游戏}**
**收入来源：{主要变现方式}**
**当前数据：**

| 指标 | 数值 |
|------|------|
| 月新增用户 | |
| 获客成本 CAC | |
| 首日付费转化率 | |
| 客单价 | |
| 月均消费频次 | |
| 月均毛利率 | |
| 月留存率 | |
| 平均生命周期 | |

**分析目标：{评估投放ROI/优化获客策略/定价决策/商业化规划}**
**回本要求：{几个月内回本}**

**请输出完整的 ROI 分析报告：**

1. **LTV 计算**
   - 计算方法说明（按月计算 vs 按生命周期计算）
   - LTV 计算过程
   - LTV/CAC 比值（健康标准 ≥3）
   - 敏感性分析（关键变量±20% 的影响）

2. **CAC 分析**
   - 分渠道 CAC 对比

| 渠道 | 月获客量 | 总花费 | CAC | 转化质量 |
|------|---------|-------|-----|---------|
| 信息流 | | | | |
| 搜索 | | | | |
| 社交 | | | | |
| 自然流量 | | | | |

   - CAC 趋势分析（是否在上升）
   - CAC 优化建议

3. **回本周期分析**
   - 月度回本曲线
   - 累计回本点
   - 不同渠道的回本周期对比
   - 影响回本周期的关键因素

4. **ROI 矩阵**

| 渠道/策略 | CAC | LTV | LTV/CAC | 回本周期 | 月度ROI | 推荐动作 |
|----------|-----|-----|---------|---------|---------|---------|
| | | | | | | |

5. **优化建议**
   - 加大投入的渠道（LTV/CAC > 5）
   - 优化投入的渠道（LTV/CAC 3-5）
   - 减少投入的渠道（LTV/CAC < 3）
   - 提升 LTV 的策略（提高客单价/复购/留存）
   - 降低 CAC 的策略（优化素材/渠道/转化漏斗）

6. **财务模型**
   - 3个月/6个月/12个月收入预测
   - 不同投放预算下的盈亏平衡点
   - 商业化时间表建议

**约束：**
- 计算过程要透明，标注每个数字的来源
- LTV 计算要考虑货币时间价值（折现率）
- CAC 要包含隐性成本（人力、工具、素材）
- 敏感性分析必须做，避免单一数字误导决策
- 区分"毛 LTV"和"净 LTV"（扣除服务成本）
- 建议要可执行，不要"提升用户价值"这种空话

## 六、增长策略

<small style="color:#888">适用场景：拉新策略、促活策略、转化策略、裂变策略设计，适用于产品各阶段的增长目标达成。</small>

<small style="color:#888">提示词：</small>

**你是一位增长策略专家，擅长根据产品阶段设计可落地的增长方案，避免"宏大叙事但无法执行"的策略。**

**请根据以下信息设计增长策略：**

**产品/业务：{描述}**
**当前阶段：{冷启动/增长期/成熟期/衰退期}**
**核心指标：{DAU/MAU/收入/留存率}**
**当前数据：{关键指标现状}**
**增长目标：{3个月内的具体目标}**
**预算级别：{零预算/小预算/中预算/大预算}**
**团队规模：{人数和分工}**
**最大约束：{技术/资金/人力/合规}**

**请输出完整的增长策略：**

1. **增长诊断**
   - 当前增长瓶颈（拉新/激活/留存/变现/传播 哪个环节最弱）
   - 增长杠杆点（哪个环节提升1倍对整体影响最大）
   - 资源盘点（有什么可以用的资产：用户/内容/渠道/品牌）

2. **北极星指标定义**
   - 北极星指标
   - 拆解公式（如：收入 = 流量 × 转化率 × 客单价 × 复购次数）
   - 衍生指标树（每个变量对应的具体指标）
   - 各团队对齐的子指标

3. **增长策略设计**（按4个方向）

**方向1：拉新策略**
   - 目标人群精准定义
   - 3个获客渠道（按优先级排序）
   - 每个渠道的：获客方式、预计CAC、预计量级
   - 冷启动特殊策略（如：邀请制/种子用户/内容种草）

**方向2：促活策略**
   - 用户激活关键行为定义（Aha Moment）
   - 新手引导优化方案
   - 3个促活机制（推送/活动/内容/社交）
   - 沉默用户唤醒策略

**方向3：转化策略**
   - 转化漏斗优化点
   - 定价策略建议（如有）
   - 3个转化提升实验（每个含假设/方案/指标）

**方向4：裂变策略**
   - 裂变机制设计（拼团/邀请/分享/UGC）
   - 裂变钩子设计（利益/社交货币/成就感）
   - K因子测算和提升方案
   - 裂变风险控制（避免刷单/封号）

4. **实验排期表**

| 周次 | 实验 | 假设 | 指标 | 预期效果 | 负责人 |
|------|------|------|------|---------|-------|
| 第1周 | | | | | |
| 第2周 | | | | | |
| ... | | | | | |

5. **风险评估**
   - 5个主要风险点
   - 每个风险的应对方案
   - 止损线设定

6. **效果评估机制**
   - 每周复盘指标
   - 每月复盘指标
   - 实验成功/失败的判定标准
   - 失败后的备选方案

**约束：**
- 策略要可执行，避免"加强品牌建设"这种空话
- 每个实验必须1-2周内可验证
- 优先选择低成本高杠杆的策略
- 裂变策略必须符合平台规则和法律法规
- 给出"如果失败"的备选方案
- 考虑团队实际执行力，避免方案超载

## 使用技巧

| 技巧 | 说明 |
|------|------|
| 提供真实数据 | 喂入真实业务数据，AI 的分析更精准可执行 |
| 分阶段生成 | 先要诊断→确认瓶颈后再要策略→最后要实验方案 |
| 指定北极星指标 | 明确告诉 AI 你的核心指标，避免策略跑偏 |
| 设置预算约束 | 告诉 AI 预算上限，避免方案超出承受能力 |
| 加入竞品数据 | 提供竞品的留存/转化数据作为基准，分析更准 |
| 要求敏感性分析 | 让 AI 标注关键变量波动对结果的影响 |
| 区分统计显著和实际显著 | A/B 测试结果要同时看 p 值和业务影响 |

## 常见问题 FAQ

| 问题 | 解答 |
|------|------|
| AI 给的留存数据不准怎么办？ | 提供真实留存数据作为输入；让 AI 标注哪些是事实、哪些是估算 |
| 增长策略太宏大无法落地怎么办？ | 加约束"每个策略1-2周内可验证"，并要求标注所需资源 |
| A/B 测试样本量计算不出来？ | 提供当前基线转化率和最小可检测效应（MDE），让 AI 按公式计算 |
| LTV 计算结果和实际偏差大？ | 检查输入的留存率是否准确；让 AI 做敏感性分析找出关键变量 |
| 用户画像太笼统怎么办？ | 提供真实用户访谈记录或行为数据，并要求"具体到可识别的真实个人" |
| ROI 分析的渠道数据缺失？ | 先让 AI 列出"需要补充的数据清单"，再分阶段完善 |
