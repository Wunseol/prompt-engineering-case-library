## 一、Agent 系统与多智能体编排

### 5.1 分层多智能体架构

<small style="color:#888">适用场景：通用 Agent 系统架构设计，采用中心化分层架构组织多智能体协作。</small>

**Role:** Agent 系统架构师，负责设计多智能体协作的分层架构方案。

**Task:** 设计通用 Agent 系统的分层架构方案。采用中心化分层架构：唯一调度 Agent 负责整体调度，工作 Agent 完全由调度 Agent 动态实例化、调度、销毁，无固定工作 Agent 池。

**Constraints:**
- 调度 Agent 唯一，承担任务分解、工作 Agent 调度、结果汇聚
- 工作 Agent 动态创建与销毁，按需实例化，避免资源常驻
- 无固定工作 Agent 池，工作 Agent 类型与数量由任务决定
- 调度 Agent 与工作 Agent 之间职责边界清晰，单向通信

**Output Format:**
1. 架构图（文本描述，标注调度 Agent、工作 Agent、通信链路）
2. 调度 Agent 职责清单与工作 Agent 实例化流程
3. 调度流程时序图（任务接收 → 分解 → 工作 Agent 创建 → 执行 → 结果汇聚 → 销毁）
4. 扩展点设计（如何新增工作 Agent 类型）

### 5.2 Agent 隔离策略

<small style="color:#888">适用场景：多 Agent 状态隔离设计，防止任务错乱、数据污染、会话串数据。</small>

**Role:** Agent 系统架构师，负责设计多 Agent 系统的状态隔离方案。

**Task:** 设计多 Agent 系统的状态隔离方案。默认隔离所有可变状态，状态不共享，上下文独立，避免共享状态导致的任务错乱、数据污染、会话串数据等问题。

**Constraints:**
- 所有可变状态默认隔离，各 Agent 上下文独立
- 状态归属明确，每个状态有唯一持有者
- 共享状态为例外，需显式声明并说明原因
- 隔离边界清晰，禁止跨边界直接引用

**Output Format:**
1. 隔离边界划分（标注每个 Agent 的状态作用域）
2. 状态归属表（状态名 → 持有 Agent → 生命周期）
3. 共享例外清单（状态名 → 共享原因 → 同步策略）
4. 隔离实现要点（数据结构、上下文传递、销毁机制）

### 5.3 流水线解耦

<small style="color:#888">适用场景：工作流灵活编排设计，多阶段模块解耦、模块化拼接、节点可自由改动。</small>

<small style="color:#888">提示词：</small>

**请设计工作流流水线解耦方案。需要将流水线的多个阶段模块解耦后重新规划排列，使流水线模块支持模块化拼接；流程不应固化，需支持从当前节点灵活拼接后续节点（如先优化、再审查、再优化）；同时需支持在对应节点循环与 LLM 交互，直至生成结果满足要求，并支持清空当前节点的生成内容与上下文，根据已有输入重新生成。**

**设计约束：**
- 节点高度解耦，单个节点可独立修改与替换
- 支持节点灵活拼接，后续节点可动态配置
- 节点内支持循环交互与上下文重置
- 节点输入输出契约标准化

**输出格式：**
1. 节点解耦方式（接口定义、数据契约、依赖管理）
2. 模块化拼接策略（拼接规则、节点注册、流程编排）
3. 循环交互机制（触发条件、终止条件、上下文管理）
4. 上下文重置策略（重置范围、状态保存、重新生成流程）

### 5.4 节点内 Loop 控制

<small style="color:#888">适用场景：人机交互式循环生成，半自动模式下节点内强交互循环。</small>

**Role:** Agent 工作流设计者，负责设计节点内循环交互机制。

**Task:** 设计节点内循环交互机制。每个节点内循环时，每次循环结束后用户均可提问，半自动模式下为强交互模式；一个节点即一个任务，由调度 Agent 统一调度控制；每个节点可调用多个 Agent 联合完成任务，并在该任务内循环。

**Constraints:**
- 每次循环结束用户可提问，支持强交互模式
- 节点即任务，由调度 Agent 统一调度
- 节点内可调用多个 Agent 联合完成
- 循环具备明确触发与终止条件

**Output Format:**
1. 循环触发条件（自动触发与手动触发）
2. 用户提问接入点（提问时机、交互方式、响应处理）
3. Agent 联合协作方式（角色分工、调用顺序、结果合并）
4. 循环终止条件（成功判定、失败判定、最大循环次数）

### 5.5 蓝图/涌现模式

<small style="color:#888">适用场景：不同生成策略的设计，蓝图模式骨架式生成与涌现模式自由发展。</small>

<small style="color:#888">提示词：</small>

**请设计以下两种生成策略：1.蓝图模式：概念、设计、详细规划、核心实现、审阅、优化，先生成骨架再逐步生成完整产出。2.涌现模式：概念、设计、规划、实现、审阅、优化，根据输入与环境让结果自由发展，不预设最终形态。**

**设计约束：**
- 蓝图模式强调骨架先行，逐步细化
- 涌现模式强调环境驱动，形态不预设
- 两种模式均需明确的阶段产物
- 对比两种模式的差异与适用场景

**输出格式：**
1. 蓝图模式流程（节点列表、阶段产物、流转规则）
2. 涌现模式流程（节点列表、阶段产物、自适应规则）
3. 差异对比表（流程节点、产物形态、可控性、适用场景）
4. 模式选择建议（按任务特征推荐模式）

### 5.6 工具延迟加载

<small style="color:#888">适用场景：工具系统性能优化，按需加载工具，最小化上下文 Token 开销。</small>

<small style="color:#888">提示词：</small>

**请设计工具延迟加载方案。对比全量工具注册与延迟加载两种方案，采用延迟加载方案：仅在 LLM 需要时实例化工具，最小化上下文 Token 开销。当前系统启动时全量注册所有工具，固定消耗大量 Token，需重构为延迟加载模式。**

**设计约束：**
- 工具按需实例化，仅在 LLM 调用时加载
- 工具索引保持轻量，最小化 Token 占用
- 支持工具回退（加载失败时的降级策略）
- 兼容现有工具注册接口

**输出格式：**
1. 工具索引设计（索引结构、元数据、查询接口）
2. 按需实例化流程（触发时机、加载流程、缓存策略）
3. Token 节省估算（对比全量注册的优化效果）
4. 回退策略（加载失败、工具不存在、超时处理）

### 5.7 工具集对齐

<small style="color:#888">适用场景：工具系统标准化，工具集设计与命名对齐通用规范。</small>

**Role:** Agent 工具系统设计者，负责设计工具集对齐与命名规范方案。

**Task:** 设计工具集对齐方案。工具集设计应与通用规范对齐，功能相似的工具命名保持一致，便于对照参考。参考已有工具代码分类结构与架构设计，所需工具可直接复用并改造适配。

**Constraints:**
- 工具命名与通用规范对齐，功能相似保持一致
- 工具分类清晰，目录结构标准化
- 支持直接复用与改造适配
- 改造清单明确，标注改造点与适配方式

**Output Format:**
1. 工具分类目录（一级分类、二级分类、目录树）
2. 命名映射表（现有名 → 标准名 → 改造说明）
3. 适配改造清单（工具名 → 复用/改造 → 适配方式）
4. 对齐检查清单（命名规范、接口规范、文档规范）

### 5.8 生命周期标准化

<small style="color:#888">适用场景：Agent 运行时管理，统一工作 Agent 生命周期钩子，调度 Agent 完全掌控工作 Agent 行为。</small>

**Role:** Agent 运行时设计者，负责设计统一的工作 Agent 生命周期管理方案。

**Task:** 设计统一的工作 Agent 生命周期管理方案。统一所有工作 Agent 生命周期钩子：onCreate → onRun → onToolCall → onEvent → onComplete/onError/onAbort，使调度 Agent 可完全掌控工作 Agent 行为。

**Constraints:**
- 生命周期钩子统一，所有工作 Agent 实现相同接口
- 钩子顺序固定：onCreate → onRun → onToolCall → onEvent → onComplete/onError/onAbort
- 调度 Agent 可在每个钩子点接管控制
- 异常处理标准化

**Output Format:**
1. 钩子触发时机表（钩子名 → 触发时机 → 调用方 → 返回值）
2. 参数约定（每个钩子的入参与出参）
3. 异常处理流程（异常捕获、错误传播、资源清理）
4. 调度 Agent 接管点（接管时机、接管操作、控制流转）

### 5.9 Swarm 集群协作

<small style="color:#888">适用场景：并行任务场景，多工作 Agent 并行执行与分工协作。</small>

**Role:** Agent 集群架构师，负责设计多 Agent 并行执行的集群协作架构。

**Task:** 设计 Swarm Agent 集群协作架构。支持多工作 Agent 并行执行（如同时生成设计、配置、设定），支持 Agent 分工协作（规划→实现→验证→优化流水线），支持进程内/多进程调度。

**Constraints:**
- 支持多工作 Agent 并行执行
- 支持分工协作流水线（规划 → 实现 → 验证 → 优化）
- 支持进程内与多进程调度
- 资源隔离与结果汇聚机制完备

**Output Format:**
1. 并行调度策略（任务分发、负载均衡、调度算法）
2. 分工协作模式（角色定义、流水线编排、依赖管理）
3. 资源隔离方案（状态隔离、上下文隔离、故障隔离）
4. 结果汇聚机制（结果收集、合并策略、冲突处理）

### 5.10 跨进程协作

<small style="color:#888">适用场景：分布式 Agent 协作，扩展消息投递层支持跨进程投递，多实例分布式协作。</small>

<small style="color:#888">提示词：</small>

**请设计跨进程 Agent 协作方案。当前消息投递层仅支持进程内，需扩展消息投递层，新增 IPC/WebSocket 跨进程投递层，支持多实例分布式协作。批量执行多任务时无响应延迟，单任务崩溃不影响全局。**

**设计约束：**
- 消息投递层扩展支持 IPC/WebSocket 跨进程投递
- 支持多实例分布式协作
- 批量执行多任务时无响应延迟
- 单任务崩溃不影响全局，具备容错隔离

**输出格式：**
1. 投递层架构（进程内投递、跨进程投递、协议适配）
2. 容错隔离方案（任务隔离、进程隔离、故障传播阻断）
3. 故障恢复策略（崩溃检测、任务重试、状态恢复）
4. 分布式调度策略（任务分发、负载均衡、节点管理）

### 5.16 Agent 安全与防护

<small style="color:#888">适用场景：Agent 安全设计，防范供应链攻击、目标漂移、提示注入等风险。</small>

<small style="color:#888">提示词：</small>

**请为以下 Agent 设计安全防护策略。**

**Agent 名称：** [名称]
**Agent 权限：** [可执行的操作]
**敏感数据：** [涉及的数据类型]

**需要覆盖：**
1. 输入验证：如何过滤恶意输入
2. 权限控制：操作是否需要确认
3. 输出审查：如何防止泄露敏感信息
4. 目标漂移检测：如何检测 Agent 偏离了原始目标
5. 工具调用限制：单次对话最大调用次数
6. 回退策略：出错时如何恢复

**设计约束：**
- 输入验证覆盖注入攻击、越权访问
- 权限控制分级（读/写/执行）
- 输出审查覆盖敏感信息脱敏
- 目标漂移检测具备阈值与告警
- 工具调用具备次数与频率限制
- 回退策略保证状态可恢复

**输出格式（Markdown 文档）：**
1. 安全威胁模型（威胁类型 → 风险等级 → 影响）
2. 六项防护策略详细设计
3. 安全检查清单（执行前/执行中/执行后）
4. 应急响应流程（异常检测 → 告警 → 隔离 → 恢复）

### 5.17 Agentic Coder 计划优先编码代理

### 5.18 Multi-Agent 协调器

<small style="color:#888">适用场景：复杂项目需要多个专业 Agent 协作完成的场景。</small>

<small style="color:#888">提示词：</small>

**你是一个多 Agent 协调器，负责将复杂任务分解并委派给专业 Agent。**

## 可用 Agent

| Agent | 专长 | 适用任务 |
|-------|------|----------|
| Researcher | 信息搜索和分析 | 数据收集、竞品分析、文献综述 |
| Coder | 代码编写和调试 | 编码、重构、Bug 修复 |
| Reviewer | 质量审查 | 代码审查、文档审查、安全审计 |
| Writer | 内容创作 | 文档撰写、报告生成 |

## 工作原则

1. 将复杂任务拆分为子任务
2. 每个子任务委派给最合适的 Agent
3. 并行执行独立的子任务
4. 汇总结果后进行最终审查
5. 如果某步失败，自动重试或切换策略

## 状态追踪

**对每个子任务，跟踪：**
- 状态：pending → in_progress → completed/failed
- 负责 Agent：[agent_name]
- 结果摘要：[result_summary]

**用户任务：** [任务描述]

**输出格式：**
1. 任务分解方案（子任务列表与依赖关系）
2. Agent 委派计划（子任务 → Agent → 并行/串行）
3. 状态追踪表（子任务 → 状态 → 负责Agent → 结果摘要）
4. 最终汇总结果（合并各 Agent 输出的综合结论）
