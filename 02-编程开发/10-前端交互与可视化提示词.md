## 一、前端重构与可视化设计

### 10.1 前端重构设计

<small style="color:#888">适用场景：前端 UI 重构，对齐业界主流智能体项目前端风格。</small>

**Role:** 资深前端架构师

**Task:** 重构优化前端代码，使其适配项目各个功能模块，构建简洁优雅的项目前端；可参考业界主流智能体项目实现方案，前端在任务执行时支持用户实时跟进与查看进度，重要节点需用户互动授权。

**Constraints:**
- 重构需覆盖项目各功能模块，确保 UI 风格统一
- 任务执行过程需支持用户实时跟进与查看进度
- 重要执行节点需用户互动授权
- 可参考业界主流智能体项目前端实现方案
- 重构方案需符合前端工程规范

**Output Format:**
输出前端重构方案，包含以下内容：
1. 重构目标与设计原则
2. 模块覆盖清单与 UI 风格统一方案
3. 实时进度跟进与查看交互方案
4. 重要节点授权交互接入点
5. 参考实现说明与技术选型

---

### 10.2 实时进度与 Trace 展示

<small style="color:#888">适用场景：智能体执行过程可视化，参考业界主流实现展示 Trace 内容。</small>

**Role:** 资深前端可视化设计师

**Task:** 调研业界主流智能体项目的 Trace 实现方案，设计项目的 Trace 可视化方案，明确 Trace 数据采集、传输、渲染与交互查看机制，使用户能够查看 Trace 内容，解决中间产物与大模型思考、执行过程不可见的问题。

**Constraints:**
- 需深度调研业界主流智能体项目的 Trace 实现方案
- Trace 数据流需覆盖采集、传输、渲染、交互查看全链路
- 方案需使中间产物、思考过程、执行过程对用户可见
- 方案需具备可扩展性与可维护性

**Output Format:**
输出 Trace 可视化设计方案，包含以下内容：
1. 业界主流方案调研对比
2. Trace 数据结构定义与采集机制
3. 数据传输链路设计
4. 前端渲染方案与组件设计
5. 交互查看与钻取机制

## 二、人机交互与数据流校验

### 10.3 人机协作交互设计

<small style="color:#888">适用场景：人机协作交互设计，三栏式布局支持与智能体交流与重要节点授权。</small>

**Role:** 资深交互设计师

**Task:** 设计三栏式人机交互布局，左侧为对话区支持与智能体交流，中间区域查看生成内容，右侧展示文件目录；明确各栏职责、数据流与重要节点的授权交互接入点，重要节点需用户互动授权。

**Constraints:**
- 采用三栏式布局：左对话、中内容、右文件目录
- 左侧对话区需支持与智能体交流
- 中间区域需展示生成内容
- 右侧需展示文件目录结构
- 重要节点需用户互动授权，明确授权交互接入点
- 各栏职责与数据流需清晰定义

**Output Format:**
输出三栏式交互布局设计方案，包含以下内容：
1. 整体布局与各栏职责说明
2. 左侧对话区交互方案（含与智能体交流机制）
3. 中间内容区展示方案
4. 右侧文件目录展示方案
5. 各栏数据流设计
6. 重要节点授权交互接入点

---

### 10.4 前后端数据流校验

<small style="color:#888">适用场景：前后端数据一致性验证，校验字段映射、类型、规则对齐。</small>

**Role:** 资深全栈工程师

**Task:** 检查前端与后端的信息传递是否正确通畅，校验前后端字段映射是否完全一致，包括字段名、字段类型、非空约束、枚举值、长度规则的对齐情况。

**Constraints:**
- 校验范围覆盖所有前后端交互接口
- 字段核对需包含：字段名、字段类型、非空约束、枚举值、长度规则
- 需检查请求方法与接口路径的一致性
- 需覆盖入参与出参结构

**Output Format:**
输出前后端数据流校验报告，包含以下内容：
1. 接口清单（接口路径、请求方法）
2. 入参结构与字段规则核对表
3. 出参结构与字段规则核对表
4. 字段映射一致性核对表（字段名、类型、非空、枚举、长度）
5. 不一致项与修复建议

## 三、端口与表单交互优化

### 10.5 端口管理优化

<small style="color:#888">适用场景：端口管理规范化，检查并优化整理项目所有端口。</small>

**Role:** 资深后端工程师

**Task:** 检查项目的所有端口，进行规范化整理（具体方案可由 AI 决策，但需符合软件开发规范），并同步更新工作目录下的 README。

**Constraints:**
- 需检查项目所有端口的占用与配置情况
- 整理方案需符合软件开发规范
- 具体整理方案可由 AI 自主决策
- 需同步更新工作目录下的 README 文档

**Output Format:**
输出端口管理优化方案，包含以下内容：
1. 当前端口使用清单
2. 端口规范化整理方案
3. 端口冲突与优化建议
4. README 更新内容

---

### 10.6 表单交互优化

<small style="color:#888">适用场景：表单交互优化，修复重复提交、参数校验、输入方式与自动生成问题。</small>

**Role:** 资深前端工程师

**Task:** 优化创建表单的交互流程，修复重复提交问题，确保创建参数不能全为空，支持手写输入与文件上传，并支持基于标题或简介自动生成内容。

**Constraints:**
- 需修复表单重复提交问题（创建成功后应退出创建页面，避免重复创建记录）
- 创建参数不能全为空，需进行非空校验
- 需支持手写输入与文件上传两种输入方式
- 需支持基于标题或简介自动生成内容
- 需明确表单校验、页面跳转、输入方式与自动生成接入方案

**Output Format:**
输出表单交互优化方案，包含以下内容：
1. 表单校验规则（含非空校验）
2. 重复提交防护与页面跳转方案
3. 输入方式支持方案（手写输入、文件上传）
4. 自动生成内容接入方案
5. 优化后交互流程说明

## 四、文件展示与全模块测试

### 10.7 文件展示与持久化

<small style="color:#888">适用场景：数据存储与前端展示，节点产物数据库与文件系统双写策略设计。</small>

**Role:** 资深全栈工程师

**Task:** 设计数据存储与前端展示方案，解决节点生成内容仅存入数据库不便于用户查看的问题，明确数据库与文件系统双写策略、文件渲染机制与前端展示链路，确保节点产物能够通过文件形式展示到前端。

**Constraints:**
- 节点产物需同时写入数据库与文件系统（双写）
- 需明确文件渲染机制
- 需打通前端展示链路
- 方案需确保节点产物能通过文件形式展示到前端
- 需保证数据库与文件系统数据一致性

**Output Format:**
输出数据存储与前端展示方案，包含以下内容：
1. 数据库与文件系统双写策略
2. 文件渲染机制设计
3. 前端展示链路设计
4. 数据一致性保障方案
5. 节点产物展示流程说明

---

### 10.8 全模块 Web 测试

<small style="color:#888">适用场景：Web 端全流程测试，操作执行核心业务跑通全部模块与工具系统。</small>

**Role:** 资深测试工程师

**Task:** 通过前端操作执行核心业务流程，全程跟踪数据流，检查并记录遇到的问题，尝试跑通项目的所有模块，包括核心模块、各个子模块以及工具系统的全面使用测试。

**Constraints:**
- 需通过前端操作执行核心业务流程
- 需全程跟踪数据流
- 测试范围需覆盖所有模块（核心模块、子模块、工具系统）
- 需记录测试中遇到的所有问题
- 需输出完整的测试报告

**Output Format:**
输出全流程测试报告，包含以下内容：
1. 测试范围与覆盖模块清单
2. 核心业务流程执行情况
3. 数据流追踪结果
4. 各模块运行情况（核心模块、子模块、工具系统）
5. Bug 清单（含问题描述、复现步骤、严重程度）
